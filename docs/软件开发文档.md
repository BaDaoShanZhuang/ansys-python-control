## 1. 总体架构

软件是一个**本机桌面控制端**，用统一界面驱动两个外部求解器进程（Ansys Mechanical、Zemax OpticStudio），把结构/热分析的节点位移转换为光学元件刚体位移/旋转并回写到光学模型、运行光线追迹、读写结果。分层如下：

```
┌─────────────────────────────────────────────────────────────┐
│  UI 层   ansys_control/gui.py                                │
│  MainWindow + 各 QDialog + 各 *Worker(QObject/QThread)        │
└───────────────┬──────────────────────────┬──────────────────┘
                │                           │
┌───────────────▼───────────┐   ┌───────────▼──────────────────┐
│ Mechanical 业务层          │   │ Zemax 业务层                 │
│ mechanical.py (会话/端口)  │   │ zemax.py                     │
│ mechanical_ops.py          │   │ (ZOS-API/刚体配准/追迹/DTS)  │
│ (journal 脚本生成/采集)    │   │                              │
└───────────────┬───────────┘   └───────────┬──────────────────┘
                │ PyMechanical               │ pythonnet (.NET)
        ┌───────▼────────┐          ┌────────▼─────────┐
        │ Ansys Mechanical│          │ Zemax OpticStudio │
        │ (后台会话)      │          │ (后台 ZOS-API)    │
        └────────────────┘          └──────────────────┘

横切关注点：config.py(路径/设置)  logging_setup.py(日志/异常)
```

**设计原则**

- **不替代求解器**：FEM 求解仍由 Mechanical 完成，光线追迹仍由 Zemax 完成；本软件只做编排、数据转换与读写。
- **后台会话、不弹原生 GUI**：Mechanical 用 PyMechanical 持久会话，Zemax 用 ZOS-API 后台连接，避免"看到的窗口≠后台对象"。
- **耗时操作全部异步**：所有求解/读取/追迹/导出在 `QThread` 中执行，UI 不阻塞，同一时刻仅允许一个后台任务。
- **关闭时才落盘**：会话内修改不立即写盘，由用户在关闭时决定，避免频繁长保存与工程锁；软件不强杀进程、不绕过原生保存。

## 4. 模块详解

### 4.1 `config.py` —— 路径检测与用户设置

- `CONFIG_DIR = %APPDATA%\WindowsDuan`（历史名，向后兼容；可用环境变量 `ANSYS_CONTROL_CONFIG_DIR` 覆盖），`SETTINGS_FILE = settings.json`。
- `detect_installation_paths()`：扫描 `C:\`/`D:\Program Files\ANSYS Inc\v*` 与常见 OpticStudio 目录，按版本号取最新，推断 `ANSYS_ROOT / RunWB2.exe / AnsysWBU.exe / OpticStudio.exe`。
- 优先级 **环境变量 > 用户配置 > 自动检测**（`ANSYS_ROOT / ANSYS_RUNWB2 / ANSYS_MECHANICAL_EXE / ANSYS_OPTICSTUDIO_EXE`）。
- `ensure_detected_path_settings()` 首启补全并写回；`apply_path_settings()` 把路径注入环境供 PyMechanical/ZOS-API 使用；`get/save_path_settings()` 供 UI 读写；`require_file()` 缺文件时报清晰错误。

### 4.2 `logging_setup.py` —— 日志与全局异常

- `setup_logging()`：`RotatingFileHandler` 写 `CONFIG_DIR/logs/app_YYYYMMDD.log`，同时输出到 UI 日志窗口。
- `_install_excepthook()`：替换 `sys.excepthook`，未捕获异常带完整堆栈进日志。
- `install_qt_message_handler()`：`qInstallMessageHandler` 把 Qt 内部告警纳入日志。

### 4.3 `mechanical.py` —— 会话与 database

- `launch_mechanical_session()` / `launch_mechanical_project_session()`：启动并**保持**后台会话；`mechanical_session_port()` 取通信端口。
- `read_mechanical_database_analysis_modules()` / `read_current_mechanical_analysis_modules()`：从会话**真实读取**分析对象（非按文件名猜测），`_analysis_records_to_modules()` 整理为表格行。
- `save_and_close_mechanical_session()`：保存/关闭并 `_wait_for_mechanical_port_to_close()` 确认端口释放（`_is_port_open()` 轮询）。
- `run_mechanical_python()`：在会话内执行脚本文本（journal）。

### 4.4 `mechanical_ops.py` —— journal 脚本生成与采集

生成在 Mechanical 进程内运行的 IronPython/journal 脚本文本，用于：读取 `AnalysisSettings.VisibleProperties` 并按类型（数字/布尔/枚举/文本）归类（`setting_kind` / `setting_record` / `collect_settings`）、采集 Tabular Data（`collect_tabular_data` 等）、采集分析条件（`collect_conditions`）、采集 Solution 结果对象（`collect_solution_results` / `is_solution_result_object`）。其中多数 `def` 是**脚本模板内的内部函数**，随脚本注入 Mechanical 端执行，结果以 JSON/报告回传。

### 4.5 `zemax.py` —— ZOS-API / 配准 / 追迹 / 探测器

- **连接**：`open_opticstudio()`、`current_opticstudio_project_info()`、`close_managed_opticstudio_project()`。
- **位移/旋转计算**：`read_lens_pose_records()` 读 Mechanical 导出；`calculate_pose_records_from_mechanical_exports()`（稳态）、`calculate_pose_time_series_from_mechanical_exports()`（瞬态）、`calculate_random_vibration_pose_frames_from_mechanical_exports()`（随机振动）；底层 `_fit_rigid_body_rotation()`、`_rotation_matrix_to_rotation_vector()`、`_fit_small_rotation()`、`_sample_multivariate_pose()`。
- **写入 Zemax**：`import_lens_poses_to_zmx()` / `import_lens_poses_to_current_opticstudio()` → `_apply_pose_records_to_nce()`（基准+增量）、`_load_or_create_pose_baseline()`。
- **追迹/探测器**：`list_zemax_detectors()`、`run_zemax_ray_trace_and_read_detector()`、`run_zemax_ray_trace_clear_detectors()`、`read_zemax_detector_result()`、`run_zemax_time_series_ray_trace()`、`run_zemax_random_vibration_ray_trace()`；底层 `_read_detector_result_grid()`、`_write_detector_grid_mat()`、`_grid_to_csv_text()`、`_false_color_png_bytes()` / `_false_color_rgb()`。

### 4.6 `gui.py` —— 界面与编排

- `MainWindow(QMainWindow)`：主窗口，含 Mechanical/Zemax 两页、左侧"控制中心"侧栏（含"当前操作"状态面板）、底部日志窗口、环境状态条。
- **Worker 类**（均 `QObject`，`moveToThread` 后运行）：`ModuleLoadWorker`、`MechanicalOperationWorker`、`MechanicalLaunchWorker`、`MechanicalCloseWorker`、`ZemaxPoseImportWorker`、`ZemaxCloseWorker`、`ZemaxDetectorWorker`。
- **对话框**：`PathSettingsDialog`、`AnalysisSettingsDialog`、`SolutionResultsDialog`、`DetectorImageDialog`；`DetectorPreviewScrollArea(QScrollArea)` 实现探测器伪彩图的鼠标滚轮缩放。
- **主题**：`_apply_style()`（浅色 QSS）、`_apply_light_palette()`、`_apply_app_font()`（微软雅黑）。

## 5. 线程模型与异步续作

**模式**：Worker（`QObject`）+ `QThread`。`MainWindow` 持有 `self.active_thread`；启动任务时 `new QThread → worker.moveToThread → 连接 started/finished/信号 → start()`。互斥：已有后台任务时再次触发会提示"当前操作还没有结束"。进度经 Qt 信号回主线程更新"当前操作"面板（状态点 idle/running/done/error）。

**两步流程的续作（pending-flag）**：瞬态/随机振动是"先导入、后追迹"。追迹按钮点击时若需要先完成导入，置标志 `self._time_series_pending` / `self._random_trace_pending`，在导入线程的 `operation_thread_finished` 回调里检查标志并继续追迹。这样把"导入→（弹框选探测器）→逐帧追迹→存 DTS"串成一条异步链，主线程不阻塞。相关锚点：`gui.py` 中 `_time_series_pending`(2084)、`_random_trace_pending`(2083)，多个 `QThread` 启动点（3395/3435/3507/3609/3689/4344/4462）。

**对话框续作**：读取设置/结果在后台完成后，分别用 `self.pending_settings_dialog` / `self.pending_results_dialog` 在主线程弹出，避免在工作线程里碰 Qt 控件。

## 6. 会话生命周期与"关闭时落盘"

**Mechanical**：选择 `.mechdb/.mechdat` 或点"读取模块"即启动并**保持**持久会话（记录端口）；后续读设置/求解/读结果/导出复用该会话。`保存设置`只写回会话内存；关闭时弹窗"保存后关闭/不保存关闭/取消"决定是否写盘 database。求解前自动清除该模块旧结果以保证结果与设置一致。

**Zemax**：后台 ZOS-API 连接；导入位移/旋转后不立即保存 `.zmx`，可先追迹确认再决定关闭时是否保存。

> 历史坑：早期"读取模块"用一次性临时会话、读完即退，导致后续操作报"未启动后台会话"。现已统一为持久会话。

## 7. 核心算法

> 完整推导见 `docs/节点位移计算整体位移和旋转_理论公式.md`，此处只给工程要点与代码落点。

**刚体配准（节点位移 → 镜片刚体位移/旋转）**，`_fit_rigid_body_rotation()`：
- 平移 = 质心位移 `t = q̄ − R p̄`（横向=偏心，沿光轴=离焦）。
- 旋转 = SVD/Kabsch：`H = Σ Pᵢ Qᵢᵀ`，`H = U Σ Vᵀ`，`R = V·diag(1,1,det(VUᵀ))·Uᵀ`（`det` 项反射保护，保证 `det R=+1`）。
- `_rotation_matrix_to_rotation_vector()`：矩阵对数/轴角 → 旋转向量 Rx/Ry/Rz（deg），即软件实际输出。
- 残差 RMS：去刚体后剩余位移 RMS，表征面形畸变，**不写入 Zemax**。
- `_fit_small_rotation()`：numpy 不可用或节点 <3 时的小角度线性化回退。

**随机振动多元正态采样**，`_sample_multivariate_pose(sigma_list, correlation, sample_count, seed)`：
- 以各自由度 1σ 为标准差，`Σ = D·C·D`（D=σ 对角阵，C=相关矩阵），Cholesky/eigh 分解后 `p = L·z`，`z~N(0,I)`。
- 默认 `C=I`（独立）；可由导出文件夹 `pose_correlation.csv` 提供 6N×6N 相关矩阵；非半正定自动投影后再采样。

## 8. 数据与文件格式

| 文件 | 位置 | 说明 |
|------|------|------|
| `settings.json` | `%APPDATA%\WindowsDuan\` | 仅存路径，属当前用户，不随工程分发 |
| `app_YYYYMMDD.log` | `%APPDATA%\WindowsDuan\logs\` | 按天滚动日志 |
| `{工程名}_mechanical_pose_baseline.json` | 工程目录 | Zemax 对象原始位置基准 |
| `lens_pose_latest.csv` / `lens_pose_time_series.csv` | 导出目录 | 每镜片刚体位移/旋转 + 残差 + 节点数 + 来源 |
| `pose_correlation.csv` | Mechanical 导出文件夹 | 可选，随机振动相关矩阵（6N×6N） |
| 探测器 `.mat` | 用户指定 | `detector`（Y×X 双精度通量矩阵）+ `detector_info` 结构体 |
| `.dts`（两种） | `zemax_time_series_results` / `zemax_random_vibration_results` | 见下 |

**DTS（自定义 ZIP 容器）有两种角色，每次追迹各生成一个**：

| 角色 | schema | 帧内容 | 用途 |
|------|--------|--------|------|
| 播放版 `xxx.dts` | `ansys_zemax_{transient,random_vibration}_detector_playback_dts_v1` | `frames/NNNN/detector.png`（全分辨率**对数伪彩图**）+ `pose.json` | 软件内逐帧循环播放 |
| 原始版 `xxx_matlab_raw.dts` | `…_matlab_raw_dts_v1` | `frames/NNNN/detector.csv`（**原始全分辨率通量矩阵**）+ `pose.json` + `matlab/load_dts_detector_series.m` | MATLAB/定量后处理 |

公共结构：根 `manifest.json`（`schema/frames/detector/frame_count/...`，每帧含 `frame_index/time_label/summary(含质心/总通量)/detector_{png,csv}/pose_json`）。MATLAB 读取见 `tools/matlab/`（已对 R2026a 验证，质心与 Python 一致）。

> 注意：播放版 PNG 是**经 `_false_color_png_bytes(log_scale=True)` 渲染的可视化**，非数值；定量分析必须用原始版 CSV。

## 9. 命名匹配与基准机制

- **匹配**：Mechanical 导出文件名解析出的名（如 `01_M1.txt → M1`）与 Zemax 非序列对象的 `Comment` 全名精确比较（不区分大小写、忽略多余空格）。不匹配 → 该镜片不更新。导入后在结果表/日志核对"匹配对象/节点数/未匹配名称"。
- **基准+增量**：写入值 = `基准原始位置 + 当前 Mechanical 增量`，重复导入不累加。基准首次取自 `.zmx` 原始位置，存 `{工程名}_mechanical_pose_baseline.json`；删除该 JSON 即可重建基准。瞬态/随机振动每帧/每样本均为"相对原始位置"的变化。

## 10. UI 与主题约定

- **主题**：浅色 + 青蓝 Teal 强调（`#14a08a`）。`_apply_style()` 设 QSS，`_apply_light_palette()` 设 `QPalette`（统一原生控件配色），`_apply_app_font()` 设微软雅黑 UI 字体。

- **探测器预览**：`DetectorPreviewScrollArea` 重写 `wheelEvent` 实现滚轮缩放，"适应窗口"复位。

## 13. 编码约定与已知陷阱

1. **导入路径陷阱**：从仓库父目录（`D:\260415\`）跑脚本会让 `import ansys_control` 命中**旧的可编辑安装包**。运行修订版必须先
   `sys.path.insert(0, r"D:/260415/ansys_python_control_revised_20260619")`，或直接在修订版目录内运行（`run_app.py` 已处理）。
2. **离屏无中文字体**：`QT_QPA_PLATFORM=offscreen` 不加载字体，中文渲染成豆腐块 □。需要截图/出图时用真实 Windows 平台并调用 `_apply_app_font`。
3. **不在工作线程碰 Qt 控件**：UI 更新一律回主线程（信号/pending-dialog）。
4. **关闭时落盘**：不要在每次改动后写盘 database/zmx；遵循"关闭时由用户决定"。不强杀 Ansys 进程、不绕过原生保存，以免 database 锁/工程损坏。
5. **行尾**：Windows 下 git 会把 LF 转 CRLF（正常告警）。
6. **大文件不进库**：安装包/7z/缓存等放在 `release/`、`tools/downloads/` 等被忽略目录。

## 14. 扩展点与路线图

- **面形误差/STAR 接口**：当前只传刚体位移/旋转 + 残差诊断；可扩展 grid sag / Zernike / STAR 把面形写入 Zemax。

- **远程求解**：Linux 远程 Mechanical 任务管理。
- **嵌入式 MATLAB 加载器同步**：`zemax.py::_matlab_dts_loader_text()` 目前为基础版，可同步成 `tools/matlab/load_dts_detector_series.m`（带质心/健壮处理）。
