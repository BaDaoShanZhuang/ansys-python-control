## 1. 软件是做什么的

本软件 把一条原本要在两套软件、多个脚本、多个文件夹之间反复手工切换的 **结构/热 → 光学(STOP)联合分析** 流程,整合到一个桌面界面里完成:

```
Ansys Mechanical 求解  →  导出镜片节点位移(含坐标)
        ↓  (本软件计算整体平移 + 旋转)
镜片刚体位移/旋转 ΔP、ΔR
        ↓  (按名称匹配写入,基线 + 增量)
Zemax 非序列工程 → 光线追迹 → 探测器光斑 / 能量 → MATLAB .mat / 伪彩图 / 时间序列(DTS)
```

**它不替代求解器**。有限元解算仍由 Mechanical 完成,光线追迹仍由 Zemax 完成。本软件负责:后台启动会话、读写设置、触发求解、读取与导出结果、把位移换算成位移/旋转、按名称写入 Zemax、跑追迹、取探测器数据。

**连接方式**

| 软件 | 连接技术 | 是否打开图形界面 |
|------|----------|------------------|
| Ansys Mechanical | PyMechanical(`ansys-mechanical-core`) | 后台会话,不弹 Mechanical 窗口 |
| Zemax OpticStudio | ZOS-API(pythonnet 调用 .NET) | 后台会话,不弹 OpticStudio 窗口 |

**当前主流程基于 Mechanical database 文件(`.mechdb` / `.mechdat`)**。旧的 Workbench 工程(`.wbpj` / `.wbpz`)脚本仍保留在 `scripts/` 下作为兼容工具,但桌面主流程已转向 database 文件,以减少工程锁与中间文件带来的不稳定。

## 2. 运行前提与安装

### 2.1 目标机器必须已具备

- **已安装并授权的 Ansys Mechanical**(随附 PyMechanical 接口)。
- **已安装并授权的 Zemax OpticStudio**(随附 ZOS-API 组件)。
- 安装包**不分发** Ansys、Zemax 及其许可证,这些必须由用户自行安装授权。

### 2.2 两种使用方式

**方式 A:安装包安装(推荐给最终用户)**

安装包内置 Python 运行时、PySide6、PyMechanical、pythonnet 等依赖,无需单独装 Anaconda。生成的安装程序为:

```
release\Windows端_Setup_V26.5.34.exe
```

**方式 B:从源码运行(开发/调试)**

- Python 环境:建议 `D:\anaconda\envs\zemax310`,要求 `3.10 ≤ 版本 < 3.12`。
- 安装依赖:
  ```powershell
  & 'D:\260415\ansys_python_control_revised_20260619\tools\install_dependencies.ps1'
  ```
- 环境自检:
  ```powershell
  & 'D:\anaconda\envs\zemax310\python.exe' 'D:\260415\ansys_python_control_revised_20260619\scripts\check_environment.py'
  ```
- 启动软件:
  ```powershell
  & 'D:\anaconda\envs\zemax310\python.exe' 'D:\260415\ansys_python_control_revised_20260619\scripts\run_app.py'
  ```
- 在 PyCharm 中运行时,务必把解释器指向同一个 conda 环境,否则会报 PySide6 / PyMechanical / ZOS-API 找不到。

### 2.3 路径检测与优先级

首次启动会自动扫描常见安装位置(`C:\Program Files\ANSYS Inc\v*`、`D:\Program Files\ANSYS Inc\v*` 及常见 OpticStudio 目录),识别四个关键路径并保存到:

```
%APPDATA%\WindowsDuan\settings.json
```

软件需要识别的四个可执行/目录:

| 项 | 默认推断位置(以 v261 为例) |
|----|------------------------------|
| ANSYS 根目录 | `D:\Program Files\ANSYS Inc\v261` |
| `RunWB2.exe` | `…\v261\Framework\bin\Win64\RunWB2.exe` |
| `AnsysWBU.exe`(Mechanical) | `…\v261\aisol\bin\winx64\AnsysWBU.exe` |
| `OpticStudio.exe` | `…\v261\Zemax OpticStudio\OpticStudio.exe` |

**优先级:环境变量 > 用户配置文件 > 自动检测。** 若设置了 `ANSYS_ROOT`、`ANSYS_RUNWB2`、`ANSYS_MECHANICAL_EXE`、`ANSYS_OPTICSTUDIO_EXE`,则优先采用。

检测不准时,在菜单 `文件 → 路径设置`,或 Mechanical 控制台点 **「路径设置」**,可重新「自动检测」或逐项「选择可执行文件」。保存后环境状态会自动刷新。

## 3. 十分钟跑通一条联动主线

> 第一次使用,按此顺序操作即可走完一条「稳态」联动。

1. **启动软件** → 顶部「环境状态」检查 Mechanical / Zemax / PyMechanical / pythonnet / PySide6 是否都为「正常」。有「缺失」先去「路径设置」。
2. **Mechanical 页 → 选择 Mechanical database**:选中 `.mechdb` 或 `.mechdat`,软件在后台启动 Mechanical 会话(界面不卡)。
3. **点「读取模块」**:中部「当前工程分析模块」表列出序号、系统名、模块名称、系统类型、物理场、分析类型、求解器。
4. **选中目标模块** → 视需要点「读取设置」改设置 → 点「求解模块」(求解前会自动清除该模块旧结果)。
5. **点「读取结果」** → 在结果窗口选中位移类结果 → **「导出当前 TXT」**(务必导出**含节点坐标 X/Y/Z + UX/UY/UZ** 的原始数据)。导出默认落在 `exports\` 下。
6. **Zemax 页 → 选择 Zemax 工程**(`.zmx`),软件后台加载。
7. **非序列导入区 → 「选择文件夹并稳态导入」**:指向第 5 步的导出文件夹。软件计算各镜片位移/旋转(平移+旋转)、按名称匹配写入 Zemax(基线+增量)。
8. **「稳态清空并追迹」**:清空非序列探测器旧数据 → 跑一次 NSC 光线追迹。
9. **「读取探测器」→ 选一个探测器 → 「快速查看选中探测器」**(全分辨率伪彩光斑,**鼠标滚轮可缩放**)或 **「完整导出MATLAB」**(导出 `.mat`)。
10. **关闭**:分别「关闭 Mechanical」「关闭 Zemax」,各自弹窗选择「保存后关闭」或「不保存关闭」。

## 4. 主界面与术语

主界面为**浅色现代主题**(白底卡片、细边框、青蓝 Teal 强调色,各面板用极淡色调按类别区分:工程/输入类淡蓝、状态/操作类淡青、表格/日志类白)。由左侧 **「控制中心」侧栏**(在 **Mechanical 页 / Zemax 页** 间切换,并集成 **「当前操作」** 面板)、各页主区、与底部横跨整宽的 **日志** 窗口组成。

**环境状态区**:单行三列(项目 / 路径或模块 / 状态)显示当前工程、Zemax 工程、RunWB2、Mechanical、OpticStudio、PyMechanical、pythonnet、PySide6 是否可用。路径过长中间省略,鼠标悬停看全。点「刷新状态」可重新检测。

**「当前操作」面板(左侧侧栏底部)**:顶部一个**状态点**直观显示状态——空闲(灰)/ 运行中(青)/ 完成(绿)/ 失败(红),右侧显示用时;其下分行显示——

| 字段 | 含义 |
|------|------|
| 阶段 | 当前任务属于 读取 / 求解 / 导出 / 关闭 / Zemax 追迹 等 |
| 状态 | 当前模块、求解状态、Mechanical/Zemax 返回信息 |
| 用时 | 从任务开始持续计时,用于判断长任务是否仍在运行 |

**耗时操作均在后台线程执行**(启动、求解、读结果、追迹、导出),界面不卡。同一时刻只允许一个后台操作,未结束时再次点击会提示「当前操作还没有结束」。

**关键术语**

- **模块 / 分析模块**:Mechanical 工程里的一个分析(静力结构、瞬态、随机振动等)。绝大多数操作都以「当前选中模块」为范围。
- **位移/旋转(Pose)**:镜片/反射镜作为刚体的整体平移(X/Y/Z,单位 m)+ 旋转(Rx/Ry/Rz,单位 deg)。
- **基线(Baseline)**:Zemax 对象的原始位移/旋转。导入采用「基线 + 当前增量」,见 §6 与 §9。
- **非序列 / NSC**:Zemax Non-Sequential 模式,本软件的追迹与探测器操作都在此模式下。

## 5. Mechanical 端操作

### 5.1 选择与连接

选择 `.mechdb` / `.mechdat` 后软件后台启动 Mechanical 会话并记录端口,之后的读设置、求解、读结果、导出都复用这个会话。**Mechanical 未成功启动时,后续操作都无法执行**——先看环境状态、日志、路径设置和 Ansys 授权。

「读取模块」会先**启动并保持后台 Mechanical 会话**(若尚未启动),再**从会话里真实读取分析对象**,不是从文件名猜测;读完会话保留,后续读设置/求解/导出可直接使用(早期版本读模块用一次性临时会话、读完即退,会导致随后操作提示「未启动后台 Mechanical 会话」,已修正)。多模块工程必须先在表里选中目标模块再操作,避免把 A 模块的设置/结果误用到 B 模块。

### 5.2 读取与修改设置(「读取设置」)

设置窗口的数据来自**当前 Mechanical 会话的真实属性**(`AnalysisSettings.VisibleProperties`),按属性类型(数字 / 布尔 / 枚举 / 文本)生成对应控件,不是写死模板。可编辑的显示为「可编辑」,无公开接口或读取失败的作为「只读」或不显示。

除分析设置外,还读取该模块下已加入的分析条件(力、温度、重力、约束、热边界等),同样按对象暴露的属性决定可读/可写。

**Tabular Data(频率/时间/幅值表)**:支持读取、「从 Excel/CSV/TXT 导入」、「打开当前 Excel」。推荐流程是把当前表导出成外部 Excel/CSV/TXT,在 Excel 里改好再「导入当前 Excel」,比在软件内逐格编辑更适合几十行以上的数据。

> ⚠️ 「保存设置」只写回**当前后台会话**,**不立即写盘 database 文件**。是否落盘由关闭 Mechanical 时选择。这样避免每改一格就触发长时间保存,也给你反悔的机会。

### 5.3 求解(「求解模块」)

- 求解**前自动清除该模块已有结果**,保证读取/导出的结果对应当前设置。**旧结果需要保留的,先备份。**
- 后台线程执行,当前操作区显示阶段/状态/用时。
- 软件会尝试配置默认求解资源(尽量用更多 CPU 核心),但能否用 GPU、能并行到什么程度,取决于求解器类型、分析类型和许可证,**最终以 Mechanical 实际执行为准**。
- 求解失败时日志显示 Mechanical 返回的错误。常见:约束不足、接触定义错误、材料缺失、网格失败、载荷非法、结果表达式错误、许可证不足。**软件不会自动改物理模型来掩盖错误。**

### 5.4 读取与导出结果(「读取结果」)

结果窗口以当前模块为范围,列出求解设置、分析条件和 Solution 下的结果对象。每次选一个结果导出,避免混乱。

| 导出 | 按钮 | 用途 |
|------|------|------|
| 文本 | 「导出当前 TXT」 | 位移/形变/力/应力等,供后续计算与位移/旋转换算 |
| 图片 | 「导出当前图片」 | 结果云图 PNG,供报告 |
| 二者 | 「导出当前 TXT + 图片」 | 一次导出文本与图片 |
| 时间/频率 | 「按时间/结果集导出」 | 设开始/结束/间隔,按结果可用的时间集或频率集生成序列 |

> 导出前软件尽量评估当前结果,避免导出未刷新对象。若结果表达式非法(例如用户自定义结果里的 `UX` 不是后处理器能识别的名称),Mechanical 会报错并显示出来,需到 Mechanical 里修正定义。
>
> **用于联动的导出,必须包含节点原始坐标 X/Y/Z 和三方向位移 UX/UY/UZ**,否则只能算平移、无法拟合旋转(见 §6)。

## 6. 从节点位移到镜片刚体位移/旋转(偏心/倾斜):原理与要求

Mechanical 给出的是**节点级位移**,Zemax 非序列对象需要的是元件的**整体刚体位移/旋转**——即横向**偏心(decenter)**、沿光轴**离焦/despace**与**倾斜(tilt)**。软件把某镜片对应的一组节点当作刚体点云,用刚体配准估计绕质心的整体平移与旋转。

### 6.1 软件实际采用的算法

设节点原始坐标 `pᵢ`、位移 `uᵢ`,变形后 `qᵢ = pᵢ + uᵢ`。

1. **整体平移 t(偏心/离焦)**:取所有节点位移的平均(质心位移)
   `t = (1/n) Σ uᵢ`。横向分量即光学偏心(decenter),沿光轴分量即离焦/despace。
2. **整体旋转 R(倾斜)——默认 SVD/Kabsch 严格刚体配准**:对去质心后的原始点 `p'ᵢ` 与变形点 `q'ᵢ` 构造协方差 `H = Σ p'ᵢ q'ᵢᵀ`,做奇异值分解 `H = U S Vᵀ`,取
   `R = V · diag(1, 1, det(VUᵀ)) · Uᵀ`。
   其中 `det(VUᵀ)` 项是**反射保护**,保证得到正交旋转(det=+1)而非镜像。随后把 `R` 经对数映射(log map)转成旋转向量 `Rx/Ry/Rz`(deg);转角很小时它与各轴小转角一致。
3. **回退**:当 `numpy` 不可用、点数少于 3 或数值异常时,自动退回到**小角度线性化**最小二乘解(`uᵢ − t ≈ ω × rᵢ` 的 3×3 法方程),状态标记为 `computed_small_angle`,Kabsch 解标记为 `computed_kabsch`。

> Kabsch 解对**任意大小转角**都精确,而旧的小角度近似在转角较大时会失真(例如绕 Z 转 30° 时小角度法约给出 28.6°)。完整推导见
> `docs\节点位移计算整体位移和旋转_理论公式.md`。

### 6.2 输出与误差含义

- 输出:每镜片一条位移/旋转记录 `name, X, Y, Z(m), Rx, Ry, Rz(deg), 面形残差RMS(m), 节点数, 来源文件`。
- **刚体配准只保留整体平移+旋转**;镜片自身弹性形变(面形误差)由**面形残差 RMS** 衡量,**不会被导入 Zemax**。该残差为去除最佳刚体平移+旋转后各节点的剩余位移 RMS,现已在位移/旋转表、`lens_pose_latest.csv`、计算日志与 JSON 中**真实输出**(早期版本仅在文档中提及但未计算)。残差越大,说明面形变化越显著、刚体位移/旋转越不足以描述真实变形。
- 若要把面形也传进 Zemax,需另行扩展(STAR / 网格面形 / Zernike 等),当前版本不含。

### 6.3 对导出数据的硬性要求

1. Mechanical 坐标系、位移与 Zemax 对象位置必须**同一坐标系**。
2. **单位必须一致或正确换算**(软件内部位移/旋转按 m / deg 记录,写入时会按 Zemax 当前长度/角度单位换算)。
3. 只导出单方向(如仅 `UX`)**无法唯一确定三维旋转**——必须三方向位移 + 节点坐标齐全。

## 7. Zemax 端操作

Zemax 页用于选择 `.zmx` 工程并做非序列相关操作。**当前版本不主动打开 OpticStudio GUI,全程后台 ZOS-API**,避免「你看到的窗口 ≠ 后台会话对象」的不一致。

典型顺序:**选择 Zemax 工程 → 选择文件夹并导入(算位移/旋转、按名称写入 Zemax)→ 追迹并保存 DTS(点击时弹框选探测器)→ 读取/查看探测器 → 导出 → 关闭(选择保存与否)**。

### 7.1 光线追迹

- 追迹使用 **Zemax 工程文件里的默认追迹设置**,软件界面不重复暴露全部追迹参数。
- 执行时先**清除非序列探测器已有数据**,再跑一次 NSC 光线追迹。
- 自动检测本机逻辑 CPU 核数,默认把 NSC `NumberOfCores` 设为全部核心。能否真跑满取决于 OpticStudio、工程规模、光线数、探测器类型与许可证。当前**不以 GPU 追迹为默认流程**。

### 7.2 探测器查看与导出(「打开探测器/时间序列(DTS)窗口」)

弹出窗口左侧为「探测器列表 / 当前结果」,右侧为「光线追迹 / 结果摘要」「时间序列(DTS) 播放控制」与「伪彩色预览」。

- 「读取探测器」:先列出探测器,避免一上来就读全部导致久等。
- 「快速查看选中探测器」:读取**全分辨率**网格并显示光斑伪彩图(不落盘数据文件);伪彩预览可用**鼠标滚轮直接缩放**(向上放大、向下缩小),「适应窗口」一键复位。
- 「完整导出MATLAB」:把选中探测器的全分辨率矩阵导出为 MATLAB **`.mat`**(含矩阵 `detector` 与元信息结构体 `detector_info`),供后续处理/绘图。
- 时间序列 **`.dts`** 文件「打开时间序列(DTS)」后**自动按顺序循环播放**所有帧,也可用进度条或「播放 / 暂停」逐帧查看,观察光斑随时间漂移;**播放时结果摘要会实时显示当前帧的质心坐标**。

## 8. 三种联动模式:稳态 / 瞬态 / 随机振动

非序列导入区提供三种模式,核心原则一致(**先由 Mechanical 结果算位移/旋转 → 写入 Zemax → 追迹/读探测器**),区别在输入文件的组织方式:

| 模式 | ① 导入按钮 | ② 追迹按钮 | 适用 |
|------|----------|----------|------|
| **稳态** | 「选择文件夹并稳态导入」 | 「稳态清空并追迹」 | 单一时刻或一组固定变形结果 |
| **瞬态** | 「选择文件夹并导入瞬态」 | 「瞬态追迹并保存为 DTS」 | 多个时间点逐帧:算位移/旋转→写入→追迹→保存 `.dts` |
| **随机振动** | 「选择文件夹并导入随机振动」 | 设「生成数量」后点「随机振动追迹并保存为 DTS」 | 以 1σ 为标准差按多元正态生成样本,逐样本追迹 |

> **瞬态与随机振动采用「先导入、后追迹」两步**:先点 ① 选文件夹导入(算位移/旋转、写入 Zemax、并显示在位移/旋转表中),再点 ② 追迹(复用 ① 选的文件夹,**点击时弹框选探测器**,`.dts` **自动存到工程目录下的默认结果文件夹**,无需再选保存位置)。稳态保留「清空并追迹」做单次快速追迹;瞬态/随机振动已**去掉单独的「清空并追迹」按钮**。
>
> **随机振动采样**:Mechanical 随机振动(PSD)分析给出各节点 1σ RMS 响应;软件据此算出每镜片 6 个自由度的 1σ 作为标准差,按**多元正态分布 N(0, Σ=D·C·D)** 生成「生成数量」个随机样本(D 为各自由度 1σ 的对角阵,C 为相关矩阵)。默认 C 为单位阵,即各镜片、各自由度独立;在导出文件夹放入 `pose_correlation.csv`(6N×6N 数值矩阵,行列顺序见计算日志)即可启用相关矩阵,把镜片间/自由度间相关性(通常来自模态分析)纳入采样。
>
> 对**瞬态/时间序列与随机振动**,每一帧/每个样本都理解为**相对原始位置的变化**,而不是相对上一帧的增量累加——所以重复运行不会把位移加两次(见 §9 基线机制)。

## 9. 文件、保存与数据管理

### 9.1 产生的文件

| 类型 | 位置 / 形式 |
|------|-------------|
| Mechanical 结果导出 | `exports\` 下的 TXT / PNG |
| 位移/旋转计算记录 | `lens_pose_latest.csv` / `lens_pose_time_series.csv` / JSON / 计算日志(含匹配对象、平移、旋转、面形残差、节点数等) |
| Zemax 探测器导出 | MATLAB `.mat` / 伪彩 PNG |
| 时间序列 / 随机振动追迹 | `.dts`(默认存 `zemax_time_series_results` / `zemax_random_vibration_results`) |
| 软件日志 | `%APPDATA%\WindowsDuan\logs\app_YYYYMMDD.log`(按天滚动,关软件后仍可追溯) |
| 软件本机配置 | `%APPDATA%\WindowsDuan\settings.json`(仅存路径,属当前用户,不随工程分发) |

### 9.2 「关闭时才落盘」原则

- **Mechanical**:读设置、改表格、导入载荷都只写回会话,**关闭时**弹「关闭后台 Mechanical」窗,选「保存后关闭」才写入 database;「不保存关闭」放弃本次修改;「取消」不关闭。
- **Zemax**:导入位移/旋转后**不立即保存** `.zmx`。可先追迹、看探测器确认光斑合理,再「关闭 Zemax」选保存或不保存。
- 软件**不强杀** Ansys 进程、**不绕过** Mechanical 的保存过程,以免造成 database 锁或工程损坏。Mechanical 保存慢通常与结果文件体积/模型复杂度/写盘行为有关。

### 9.3 基线 + 增量(避免重复叠加)

写入 Zemax 的位移/旋转 = **原始基线 + 当前 Mechanical 增量**,不是在上次导入结果上继续累加。软件会保存/读取每个 Zemax 对象的原始基线位移/旋转(可从 `.zmx` 文本或 NCE 行解析,并写出 `*_mechanical_pose_baseline.json`),导入时始终以基线为起点叠加当前增量。**同一组结果重复导入,位移不会被加两次。**

## 10. 命名匹配规则(最容易出错的一步)

Mechanical 与 Zemax 的关联**完全依赖名称匹配**:

- Mechanical 导出的结果文件名(或命名选择名称)需能解析出镜片标识,例如 `01_M1.txt` 解析出 `M1`。
- 该标识必须与 Zemax 非序列对象的 **`Comment`** 一致(例如 Zemax 中某镜片 Comment 为 `M1`)。
- 软件读取导出文件夹后,按名称把对应镜片的位移/旋转写入对应 Zemax 对象。

**名称不一致 → 软件无法判断该写入哪个镜片 → 该镜片不会被更新。** 导入后请在位移/旋转表与日志里核对「匹配对象」「节点数」「未匹配名称示例」。

## 11. 常见问题与排查表

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 选了文件但读模块/求解/导出都失败 | 后台 Mechanical 未成功启动 | 看环境状态/日志/路径设置/Ansys 授权;确认 `AnsysWBU.exe` 路径正确 |
| 环境状态某项「缺失」 | 路径未检测到或依赖缺失 | 「路径设置」重新自动检测或手动选;源码运行确认 conda 环境 |
| 位移/旋转只有平移、旋转为 `not_computed` | 导出 TXT 没有节点坐标 | 重新导出**含 X/Y/Z + UX/UY/UZ** 的原始数据 |
| 提示缺少某方向位移 | 只导出了单方向(如仅 UX) | 导出三方向位移文件,确保有共同节点 |
| 某镜片在 Zemax 没变化 | 名称未匹配 | 核对文件名解析出的名 ↔ Zemax 对象 `Comment`(§10) |
| 重复导入光斑跳变异常 | 误以为是累加 | 本软件是基线+增量,不累加;检查是否换了基线或工程 |
| 结果导出报表达式错误 | 用户自定义结果表达式非法 | 到 Mechanical 修正结果定义为 API 可识别的表达式 |
| 改了 Tabular Data 重开却没变 | 未在关闭时保存 | 关闭 Mechanical 时选「保存后关闭」 |
| 追迹没跑满 CPU | 求解器/工程/许可证限制 | 属正常,以 OpticStudio 实际为准 |
| 提示「当前操作还没有结束」 | 已有后台任务在跑 | 等当前任务结束,看「用时」判断进度 |

## 12. 适用范围与已知边界

**适合**:在 Mechanical 中对镜筒/支架/镜片/反射镜做静力、瞬态或随机振动分析,导出节点位移;软件算每个镜片的整体平移与旋转;写入 Zemax 非序列系统;跑追迹看探测器光斑变化。可快速比较不同工况下的**光斑偏移、能量分布变化、结构变形对光学系统的影响**。

**当前边界(请知悉)**

1. 位移/旋转导入是**刚体平移+旋转**,**不含面形误差**;镜片明显翘曲时只导入等效整体位移/旋转。
2. 旋转默认采用 **SVD/Kabsch 严格刚体配准**(对任意大小转角精确,含反射保护),仅在 numpy 不可用或有效节点过少时回退小角度近似;并输出**面形残差 RMS** 表征偏离纯刚体的程度。
3. 欧拉角分解与旋转顺序相关,写入 Zemax 时角度约定须与对象 Tilt 定义一致。
4. 软件是自动化控制端,**最终验证仍以 Ansys Mechanical / Zemax OpticStudio 原软件为准**——任何自动化结果都应结合原模型的单位、材料、边界条件与求解消息确认。

**后续可扩展方向**:更完整的属性编辑器、Tabular Data 双向同步、结果对象筛选、多探测器批量导出、面形误差/STAR 接口、远程 Linux 求解任务管理、项目级配置、自动报告与版本化实验记录。
